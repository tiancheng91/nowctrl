# P1 native protocol validation — 2026-10-20 (Asia/Shanghai)

Status: **protocol codec complete; P1 control loop not accepted**. Physical
validation is deferred at the user's request. P0 remains unaccepted, with its
existing emulator RTOS-startup blocker documented separately in [P0](p0.md).

## Delivered behavior

`src/lib.rs` is a platform-independent `no_std` library in the existing crate;
there is no workspace split or new dependency. Firmware dependencies now apply
only to bare-metal targets, so native library tests do not try to compile HAL
peripheral drivers for macOS/Linux.

The protocol codec implements the SPEC section 6.1 v1 envelope: explicit
little-endian fields, an 18-byte header, a maximum 200-byte frame, exact length
checking, reserved flags, and known message type assignments. Encoding validates
before writing and leaves the output untouched on error.

Switch payloads support OFF/ON/TOGGLE and nonzero-duration PULSE, with exact
payload lengths. ACK payloads distinguish Applied and Rejected. Control and ACK
frames require nonzero destination Node ID and request ID. Sequence zero is
allowed, including eventual wraparound; freshness/replay policy is not part of
this codec. Other message types reserve their numbers but currently validate
only their envelope; they have no implemented payload handlers.

The P0 radio still sends the original discovery strings. This change does not
add an actuation path, paired identity checks, retry logic, ACK correlation or
request deduplication. A valid decoded frame is not an authorized request.

- **11 native protocol tests passed**: [test output](logs/p1-host-tests.log).
- Native library Clippy passed with warnings denied: [output](logs/p1-host-clippy.log).
- Both firmware roles still link: [Controller](logs/p1-controller-build.log),
  [Node](logs/p1-node-build.log).
- Formatting and the existing two Python evidence-checker tests passed.
- The GitHub Actions workflow was added for Ubuntu native tests/lint/formatting,
  Python evidence-checker tests, both firmware builds and invalid role rejection.
  **Remote CI has not run**; no commit or push was performed.

The protocol cases cover the golden wire bytes, all assigned message types,
every truncated prefix, extra bytes, declared-length mismatch, 200-byte boundary,
insufficient output capacity, unknown version/type/flags, action/ACK enum and
length validation, zero pulse duration, zero control destination/request, and
unchanged output on encoding error. Every single-byte mutation of the golden
frame plus 4,112 deterministic arbitrary byte sequences (lengths 0–256) is decoded
without panics; accepted frames reencode exactly. This is a bounded robustness
check, not a fuzzing campaign or a security certification.
